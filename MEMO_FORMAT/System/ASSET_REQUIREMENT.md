# ASSET_REQUIREMENT

## PURPOSE

MVP 시스템 설계에 필요한 모델, 리깅, 애니메이션, 환경 오브젝트와 오디오의 요구사항을 관리합니다. 확보 이력은 DONE, 확보 작업과 우선순위는 TODO를 따릅니다.

## CURRENT_DECISION

- 최종 캐릭터 모델 확보 전까지 더미 모델로 시스템 구현을 우선합니다.
- 토끼 / 개 / 여우 / 담비 / 필요 시 곰은 Meshy AI 제작을 고려합니다.
- 까마귀는 현재 확보한 에셋 사용을 우선합니다.
- 뱀은 제외하며 플레이어 공격 표현은 담비에 마련합니다.
- NPC 토끼 약 8마리는 기본 모델을 재사용하고 Material 또는 가벼운 외형 변경으로 구분할 수 있습니다.

## ANIMATION

### 공통

- 기본 이동 동작: Walk / Jump.
- 대기 동작: Idle.
- Run / Turn 전용 애니메이션은 현재 필수가 아닙니다.
- Carry / Hold는 플레이어 업무 운반과 여우 납치 등에 사용되므로 중요도가 높습니다.

### 캐릭터별 후보

- 토끼 NPC: Idle / Walk / Dance / Panic·놀람 / Struggle / Carry·Hold
- 개: Idle / Walk / 선택적 Tail Wag
- 곰: Idle / Walk / Eat / 양손 휘두르기 / 선택적 Grab과 Carry. Eat 애니메이션 연결은 확보 후 진행합니다.
- 까마귀: Idle / Fly / Walk
- 담비: Idle / Walk / Attack / 선택적 뒤지기 / Carry와 Hold
- 여우: Idle / Walk / Grab / Carry / 필요 시 Attack

## ENVIRONMENT

- 조리실: 조리대 / 냄비·팬 / 조리 도구 / 접시 / 음식·재료 / 트레이 / 창문
- 창고: 여러 상자 / 자루 / 병·통 / 선반 / 재료·의류 박스 / 잡동사니
- 파티룸: 테이블 / 의자 / 접시·컵 / 풍선·가랜드·장식 / 음식 / 스피커
- 드레스룸: 옷장 / 옷걸이·옷 / 커튼 / 파티션 / 거울 / 의상 더미 / 액세서리
- 같은 모델의 위치 / 회전 / 활성 상태 변경으로 여러 Anomaly를 만들 수 있게 구성합니다.

## AUDIO

재생 모듈 / 기존 함수 연결 / 씬 수명 / 미정 정책은 [AUDIO](AUDIO.md)를 따릅니다. 아래는 음원 요구사항이며 구현 완료 목록이 아닙니다.

### 게임플레이 SFX

- 조리: 시작 / 조리 중 반복 / 타이밍 성공 / 최종 완성 / 실패 / 음식·접시 집기·놓기 / 섭취
- 공용 상호작용: 가벼운·무거운 물건 이동 / 집기·놓기 / 조사 / 성공·실패
- 문·환경: 문·옷장·창문·커튼 / 상자 이동 / 물건 낙하 / 필요 시 풍선
- Anomaly 힌트: 달각 / 사락 / 쿵 / 긁는 소리 등 위치성 오디오
- 동일 종류 SFX는 반복감을 줄이도록 2~4개 Variant를 우선 고려합니다.

### 캐릭터 SFX

- 개: 짖음 / 낑낑 / 신남·만족 / 발소리
- 곰: 낮은 울음 / 섭취 / 포효·격분 / 무거운 발소리
- 까마귀: 울음 / 날갯짓
- 담비: 뒤적임 / 작은 울음 / 빠른 발소리 / 공격
- 여우: 일반·위협·격분 울음 / 납치·공격 효과음
- 토끼 NPC: 보이스 블립 / 놀람 / 기쁨 / 파티·공포 / 포획 중 푸닥푸닥 / 구조 반응. 공용 음원에 Pitch 변화를 적용할 수 있습니다.

### Footstep / UI / Music

- 발소리: 플레이어 걷기 / 달리기, 토끼 NPC / 소형 Enemy / 대형 Enemy별 랜덤 Variant. 점프와 착지음을 함께 검토하며 바닥 재질별 분리는 현재 필수가 아닙니다.
- UI: 버튼 / 패널 / 상호작용 성공·실패 / 경고 / Anomaly 해결 / 업무 완료 / 시간 경고 / 결과 표시
- 음악: 전체 준비 BGM / 파티룸 Diegetic Music
- 결과: 성공·실패 Result Sting과 환경음 조합으로 비용을 줄일 수 있습니다.
