# MULTIPLAYER

## PURPOSE

싱글·멀티 공통 콘텐츠, 협동 역할 분담과 핵심 동기화 범위를 관리합니다.

## SYNC_BOUNDARY_DESIGN

네트워크 구현 완료나 호스트 / 권한 소유 구조의 확정을 뜻하지 않습니다.

| 구분 | 대상 |
| --- | --- |
| 공유 상태 | 플레이어 업무 / 운반, NPC 위치 / 안전, 적 행동 / 결과, 공간 변화 / 준비 / Mood |
| 로컬 표시 | 소유 플레이어의 1인칭 카메라 / 자기 모델 숨김, 개인 입력 / HUD |
| 원격 표시 | 다른 플레이어의 월드 모델 / 보유 아이템 / 행동 |
| 미정 | 상호작용 요청의 권한과 동시 입력 충돌, 접속 종료 처리 |

자기 모델 숨김은 렌더러 표시 경계이며 공유 플레이어 객체의 비활성화가 아닙니다. 로컬 ViewHoldPoint와 월드 WorldHoldPoint 분리, 권한 충돌 / 접속 종료는 후속 결정입니다.

## CURRENT_DECISION

- 싱글과 멀티 모두 NPC 토끼 약 8마리와 동일한 핵심 업무·포식자 시스템을 사용합니다.
- 공간과 업무 분리로 조리실 / 창고·운반 / 파티룸 / 드레스룸 담당이 자연스럽게 나뉠 수 있습니다.
- 포식자 이벤트가 발생하면 고정 역할이 깨지고 가까운 플레이어가 즉시 지원하는 구조를 지향합니다.
- 클래스가 있더라도 특정 직업이 없으면 핵심 행동 자체가 불가능한 구조는 피합니다.
- MVP에는 핵심 멀티플레이 상태 동기화를 포함합니다.

## SYNC_SCOPE

- 플레이어의 업무 진행과 운반 아이템 상태
- NPC 토끼의 위치 / 안전 / 납치 상태
- 포식자의 등장 / 표적 / 행동 / 성공·실패 상태
- 공간 오브젝트 변화 / 파티 준비 / Mood / 피해 상태

## LOCAL_PRESENTATION

- 임시 모델 교체 완료 후 각 클라이언트의 1인칭 화면에서 자기 플레이어 모델만 숨깁니다.
- 각 플레이어는 다른 모든 상대 플레이어 모델을 볼 수 있어야 합니다.
- 자기 모델 숨김은 로컬 표시 처리이며 네트워크로 전체 플레이어 오브젝트를 비활성화하지 않습니다. 이동 / 충돌 / 상호작용은 유지합니다.
- 보유 아이템은 로컬 ViewHoldPoint 표시 모델과 실제 WorldHoldPoint 월드 모델을 분리하는 방향입니다.
- 플레이어 집기 이후 보유 자세 전환은 멀티플레이 구현 시 함께 진행합니다. 원격 플레이어의 보유 아이템 표시와 애니메이션 상태 연결 / 해제를 맞추며, 파라미터와 자세 구성은 그때 결정합니다. 공용 [AnimatorHandler 계획](UI_PRESENTATION.md#animator_handler_plan)의 현재 싱글플레이 구현 범위에는 포함하지 않습니다.
- 현재 싱글플레이용 HoldItem 레이어 전환을 멀티플레이 전체에 그대로 적용하지 않습니다. 소유 클라이언트의 표시와 원격 클라이언트의 월드 표시를 구분합니다.
- 구체적인 소유권 판정 / 렌더러·카메라 구성은 멀티플레이 구현 시 결정합니다.
