﻿# EDITOR_TOOLS

## PURPOSE

Unity 제작 / 디버깅 툴의 현재 사용 방법과 도입 후보를 관리합니다. DEBUG_INSPECTOR / DEBUG_IMPROVEMENT / TARGET_SETTINGS / FOOD_AND_RECIPE_IMPORT / CARROT_SOUP_SETUP은 현재 구현 기준이며 나머지는 필요에 따라 도입할 후보입니다. 완료 기록과 사용자 실행 확인 범위는 DONE을 따릅니다.

## EDIT_AND_PREVIEW_BOUNDARY

| 작업 | 변경 / 저장 경계 |
| --- | --- |
| 조회 / 검사 | 대상 / 범위를 선택하고 현재 설정과 검사 결과만 표시 |
| 설정 적용 | 기존 참조와 적용 범위를 검증한 뒤 선택 항목만 변경 |
| 저장 / Undo | 씬 Dirty / Prefab Override / 원본 에셋과 지원하는 Undo / 저장 범위를 도구별로 구분 |
| 중간 실패 | 이미 변경된 대상과 실패 내역을 보고 |

원본 에셋 저장과 씬 수동 저장을 동일시하지 않으며, 플레이 진단 버튼은 기존 런타임 기능에 실제 영향을 줄 수 있습니다.

UI_EFFECT_MANAGEMENT의 미리보기는 기준 표시값 저장 → 연출만 재생 → 중단 / 창 닫기 / 플레이 전환 / Assembly Reload에서 Tween 중지와 기준 복원 순서의 설계 계약입니다. 구매 / 제작 / 보상은 실행하지 않으며 모든 Editor 도구의 구현 완료를 뜻하지 않습니다.

## DEBUG_INSPECTOR

- GameFlowData 인스펙터의 미션 설정 검사 버튼은 데이터의 공용 검증을 호출하고 통과 / 오류를 표시합니다. FlowData 필드 변경 시 이전 결과를 지우며 참조 후보 에셋을 별도 수정한 경우 재검사합니다. 검사로 추첨 / 에셋 변경 / 자동 보정은 수행하지 않습니다.
- 플레이 중 GameFlowController 인스펙터와 플레이 디버그의 전체 / 설정 탭은 `GameFlowControllerEditor.DrawSettings`를 공유합니다. 현재 선택 난이도와 적용된 FlowData / MinigameMap / Pressure / SpawnMap / Mood / Score 참조를 읽기 전용으로 표시합니다. Settings가 없으면 기본 난이도를 선택값으로 표시하지 않고 `설정 준비 전`으로 안내합니다.

### 플레이 검증용 재시작

- 에디터 플레이 중 Game 뷰에 포커스를 두고 R키를 누르면 PlayScene이 속한 저장된 씬을 Single 방식으로 다시 불러옵니다. 빌드 씬 목록 등록은 필요 없으며 정식 빌드에는 포함하지 않습니다.
- 플레이 중 임시 변경은 사라지며 추가로 열린 씬도 닫힙니다. 편집 상태로 돌아가거나 플레이 중 값을 저장하는 기능은 아닙니다. 실행 확인 항목은 [TODO](../TODO.md#gameplay_implementation), 확인 이력은 [DONE](../DONE.md#editor--debug-도구)를 따릅니다.
- 적 상태 인스펙터 / 로그 일괄 설정 / 컴포넌트 일괄 추가는 현재 지원 기능이 아니며 [TODO](../TODO.md#debug_next)에서 관리합니다.
- PlayScene의 DebugNpcDeparted는 GameFlow에 NPC 전멸 종료 조건만 주입합니다. 실제 NPC 이탈을 실행하지 않으며 NPC 상태나 Safety 평가에는 영향을 주지 않습니다.

- 대체 / 교체를 포함한 사건 공통 화면에서 해결 / 사후 처리 시간과 만료 대기를 표시하고 종료 기록에 Expired를 포함합니다. 만료 대기의 의미는 [ANOMALY](ANOMALY.md#event_lifecycle)를 따릅니다. 이동 / 교체는 사건 종료 이후에도 등록 대상의 정상 기준 갱신 대기 사유를 표시합니다.
- 대체 / Replace: 지정 / 등록 후보 발생, 유형 / 조사 ID / 상태 / 현재 매트리얼 또는 외형과 복원 기준 이름 / 실패 사유를 조회합니다.
- 교체 / Swap: 두 관련 대상, 원래 배치 대상, 대상별 완료와 0/2 / 1/2 / 2/2 진행도를 제공합니다. 공통 화면에서 양쪽 대상 이름과 찾기 / 선택을 지원합니다.

- 공통 구현: AnomalyEvent/!_Common/04. Debug/Editor/AnomalyEventSystemEditor.cs가 AnomalyEventSystem의 모든 자식에 적용됩니다. 플레이 중 Presenter 하나를 선택하면 기존 설정 아래에 디버그 영역이 표시됩니다. 다중 선택에서는 실행하지 않습니다.
- 현재 사건: 발생 건 ID / 종류 / 모든 관련 대상 / 상태 / 남은 시간 / 잠금과 진행 / 복구 대기 건수를 표시합니다. 선택은 ID로 유지하고 선택 건이 없으면 남은 첫 사건을 자동 선택합니다. 발생 건 ID는 ShakeId / InvestigationId와 별개입니다.
- 상세 표시: 개폐의 현재·복구 열림 여부 / 회전의 현재 각도와 0도 기준 / 흔들림의 동작 여부와 사건·현재 조사 ID / 낙하의 보유 상태와 정상 배치 대상을 제공합니다. 기능별 GetDebugDetails와 테스트 API를 재정의하며 기능별 필드를 공통 데이터에 모으지 않습니다.
- 발생 요청: 지정 대상과 등록 후보 버튼이 RequestDebugStart를 통해 기존 발생 함수를 호출합니다. AnomalyStartResult는 성공 여부 / 사건 / 대상 / 실패 정보를 반환합니다. 기존 TryStart(out AnomalyEvent)와 링커 호출은 유지합니다.
- 실패 사유: 실제 검사 지점에서 결과를 전달하며 로그 문자열을 수집하거나 Inspector에서 규칙을 다시 판단하지 않습니다. AnomalyStartFailure는 분류 / 코드 / 설명을 보관합니다. 기존 StartFailure enum은 호환 변환하고 새 기능별 코드는 별도 분류로 확장합니다. 등록 후보 전체 실패는 '발생 가능한 후보 없음'으로 표시합니다.
- 기능 버튼: 선택한 발생 건에서 개폐 열기·닫기·전환 / 흔들림 조사 처리 / 랜덤 회전을 기존 기능 Presenter로 요청합니다. 실행 직전 같은 발생 건과 기능 상태를 다시 확인하고 조사는 저장한 ShakeId를 사용합니다. 낙하는 실제 운반·배치로 확인하며 강제 해결 버튼을 제공하지 않습니다.
- 입력 구분: 기능 버튼은 E 홀딩 / 조준 / 거리 검사를 생략합니다. 실제 입력 경로 확인은 플레이어 조작으로 진행합니다. 기능 테스트와 강제 성공 처리를 동일시하지 않습니다.
- 최근 종료 기록: Presenter별 최대 20건, ID / 종류 / 모든 대상 이름 / 종료 당시 상세 / Resolved / Recovered / Expired / Cancelled / 플레이 경과 시각을 값으로 복사합니다. Failed는 현재 복구 대기 목록에 남습니다. 기록은 사건 / 콜백 / 대상 객체를 보관하지 않으며 지우기 버튼과 플레이 세션 변경 시 초기화를 제공합니다.
- Editor는 0.2초 간격으로 목록과 상세 표시를 갱신하고 표시 목록을 재사용합니다. 관련 대상 찾기·선택을 지원하며 플레이 종료 또는 사건 소멸 시 선택 정보를 정리합니다. UnityEditor 의존은 Editor 폴더에만 둡니다.
- 확장 방법: 새 사건 Presenter는 공통 조회와 지정 대상 요청 경로를 제공하고, Occurrence는 필요한 상세·관련 대상·기능 동작만 추가합니다. 종료 콜백에서는 정리 전에 RecordDebugStatus를 호출합니다.
- 추가 도구 후보와 우선순위는 [TODO](../TODO.md#debug_next)를 따릅니다. 부작용 없는 최종 발생 가능 사전 판정 API는 제공하지 않으며 실제 발생 결과 표시와 구분합니다.

- 적 조회와 디버그 요청 함수는 런타임 본체와 같은 어셈블리의 partial .Debug.cs에 있으며 UNITY_EDITOR로 제한합니다. 실제 이동 / 사건 / 포획 처리와 실행 기록은 본체가 담당하고 개별 적의 테스트 메뉴 대신 플레이 디버그 요청 경로를 사용합니다.

## DEBUG_IMPROVEMENT

- 공통 상세는 관련 대상별 이름 / 잠금 / 보유 / 정상 배치 / 기준 갱신 대기 사유와 사건별 상세를 함께 표시합니다. 개별 Occurrence는 기능별 상세와 동작을 제공하며 Editor에 사건 규칙을 복제하지 않습니다.
- '등록 대상 조회 / 발생 진단'을 펼쳐 이름 검색과 상태 필터를 사용합니다. 잠금 / 보유 / 기준 갱신 대기 / 정상 기준 없음 / 선택 사건 기능 없음으로 좁혀 지원 기능과 활성 상태를 조회합니다.
- 등록 대상 조회는 읽기 전용입니다. CanStart나 공간 검사를 실행하지 않으며, 기능이 있다는 표시를 실제 발생 가능 보장으로 해석하지 않습니다. 사건 시간 설정과 관리자 활성 여부도 확인합니다.
- 실패 목록은 실제 디버그 발생 요청에서 보고된 제외 사유를 표시합니다. 요청마다 초기화하며 총 실패 수와 처음 50건의 대상 / 분류 / 코드 / 설명을 보관합니다. 적의 발생 요청 전체를 수집하는 기록은 아닙니다.

| 메뉴 | 메뉴: Tools/Anomaly/대상 설정 관리. AnomalyTargetSettingsWindow와 AnomalyTargetSettingsUtility가 기존 컴포넌트의 직렬화 설정을 조회 / 비교 / 편집합니다. |

| 조회 범위 | '열린 씬 / 실행 중 대상': 비활성 오브젝트와 실행 중 생성된 대상을 포함합니다. '프리팹 원본': 기본 Assets/04. Prefabs 또는 지정한 Assets 내부 폴더를 검색하며 모델 프리팹은 제외합니다. |
| 사용 안내 | '사용 방법': 편집 순서, 개별 / 일괄 편집, 저장 / Undo, 플레이 제한, 누락 확인을 접기 / 펼치기로 안내합니다. 설명 탭 왕복은 검색 / 선택 / 스크롤을 유지하며 설명을 보는 동안 대상 검색을 보류합니다. |
| 사용 안내 | 씬과 프리팹 간 범위 변경 또는 플레이 전환은 선택을 해제합니다. |
| 컴포넌트 선택 | 설정 컴포넌트는 AnomalyTarget과 같은 오브젝트에 붙은 스크립트에서 선택합니다. 이름 / 경로와 선택 컴포넌트 없음 / 중복 필터를 제공합니다. 사건별 허용 설정을 새로 만들거나 필요한 컴포넌트를 자동 추가하지 않습니다. |
| 값 / 배열 편집 | 단일 값은 목록에서 수정하고 배열 / 복합 설정은 대상을 체크한 뒤 하단 상세에서 편집합니다. 여러 대상의 서로 다른 값은 혼합 표시하며 지정한 항목만 일괄 편집합니다. 컴포넌트가 없거나 중복인 대상은 제외합니다. |
| 선택 / 검색 | 검색에 가려진 선택 대상도 일괄 편집에 포함합니다. '검색 결과 전체 선택'은 기존 선택을 현재 검색 결과로 교체합니다. 배열은 같은 인덱스끼리 편집하며 크기 변경도 선택 대상에 적용하므로 원소 의미 / 순서가 다르면 개별 편집합니다. |
| 씬 / 프리팹 저장 | 씬 편집은 인스턴스와 프리팹 재정의에 반영하며 원본에 자동 적용하지 않습니다. 씬은 Unity에서 별도로 저장합니다. '편집한 프리팹 저장'은 이 창에서 편집한 원본 에셋을 저장하므로 같은 에셋의 다른 미저장 변경도 포함됩니다. |
| 씬 / 프리팹 저장 | 편집은 Undo / Redo를 지원하며 SO 참조 편집이 SO 내부 내용 수정으로 이어지지는 않습니다. |
| 플레이 중 편집 | 플레이 중에는 씬 인스턴스의 ReplaceController._types 유형 / 가중치 목록만 임시 편집하며 다음 발생 요청부터 반영합니다. 나머지 설정과 프리팹 원본은 읽기 전용이며 원본 저장도 막습니다. |
| 플레이 중 편집 | 실행 중 표시값이 초기화 때 복사된 모델의 실제 값과 항상 같다고 보장하지 않습니다. |
| 검증 / 이력 | 실행 검증은 [TODO](../TODO.md#debug_next), 구현 / 사용자 확인은 [DONE](../DONE.md#editor--debug-도구)를 따릅니다. |
| 공유 설정 후보 | 공통 설정 SO / 대상별 재정의는 별도 후순위 검토 항목입니다. 우선순위는 [TODO](../TODO.md#debug_next)를 따릅니다. |

- 변칙 대상 일괄 편집은 선택한 컴포넌트가 실제로 있는 대상만 적용하고 없는 대상은 제외합니다. 존재 장애물 마스크는 PresenceDisplayController가 아니라 PresenceController._obstacleMask에서 선택합니다. 표시 / 참조와 등장 공간 판정 설정의 소유자를 구분합니다.

## SOUND_SETUP

- Tools/Sound/사운드 설정에서 SoundData별 설정과 대상 컴포넌트의 연결을 처리합니다. 같은 데이터를 여러 용도에 재사용할 수 있으며 데이터 필드를 미지정하면 해당 연결은 적용하지 않습니다.
- 기존 값 교체와 기존 AudioSource 설정 변경은 별도 옵션입니다. 출력 그룹을 지정하지 않으면 기존 출력을 유지합니다. 캐릭터 / 제작의 독립 재생과 UI 공용 2D 출력을 구분합니다.
- 적별 대상은 BothersomeSound / DemandSound / HarmSound / KidnapSound / StealSound이며 실제 행동에 맞는 데이터만 연결합니다. 신규 연결 설정과 기존 EnemySound 데이터의 자동 이전은 별개의 기능입니다.
- 재생 책임과 필드 대응은 [AUDIO](AUDIO.md), 구현 / 실행 이력은 [DONE](../DONE.md#오디오), 추가 이전 / 연결 작업은 [TODO](../TODO.md#presentation_and_audio)를 따릅니다.

## PRESENCE_MAP_CHECK

- 메뉴: Tools/MapChecks/Presence/InspectSelection, Tools/MapChecks/Presence/RepairSelection. 씬 또는 Prefab Mode의 Hierarchy에서 맵 루트 / 객체를 선택합니다. 기존 변칙 대상 설정 창의 체크 목록과 별개입니다.
- InspectSelection은 선택 계층의 비활성 자식까지 PresenceDisplayController를 중복 없이 수집해 변경 예정 값을 Console에 표시하며 수정하지 않습니다. 플레이 / 전환 중 실행과 Project 창의 원본 에셋 직접 적용은 제외합니다.
- RepairSelection은 정상 참조를 유지하고, 구성 오류가 있을 때 전체 메시를 포함하는 단일 직계 자식과 비트리거 대표 Collider를 찾습니다. Collider는 표시 Target의 자식까지 조회하며 활성 상태와 무관하게 후보를 판별합니다. 이름으로 Visual / Body를 강제 검색하지 않습니다.
- 명확한 Target / Collider만 보완하고 해당 대표 Collider만 켭니다. 복구 조사 Collider를 켜거나 모든 자식 Collider를 활성화하지 않습니다. 복수 후보, 동일 객체의 PresenceDisplayController 중복, 복구 조사 계층 충돌 / 동일 Collider, 초기 AppearanceComponents.MainCollider 불일치는 보완 제외 사유를 표시합니다.
- 설정 변경은 Unity 직렬화 / Prefab Override API로 기록하고 하나의 Undo 그룹으로 묶습니다. 맵의 모든 Override를 초기화하거나 원본에 자동 적용하지 않습니다. 자동 저장하지 않으므로 씬 / Prefab Mode를 별도로 저장합니다.
- 일반 참조 구성의 기존 값 유지 정책과 ItemWorldController용 공용 Collider 검색은 유지합니다. 이 명령은 Presence 구성 보완이며 전체 맵 / 데이터 / NavMesh / 플레이 통과를 보장하지 않습니다.
- 반영 / 사용자 확인은 [DONE](../DONE.md#2026-10-06-플레이-준비-보완), 실행 검증은 [TODO](../TODO.md#latest_play_readiness)를 따릅니다.

## INGREDIENT_STOCK_DEBUG

- 재고 기능은 통합 PlayDebugWindow의 버튼이 아니라 공급원의 `IngredientSource` 컴포넌트 컨텍스트 메뉴에 있습니다. 통합 창의 기록 탭에서도 실행 결과를 볼 수 있습니다.
- `Debug/재고 상태 확인`: 공급 수량 / 외부 사용 객체 / 소비 후 보관 대기 / 재사용 가능 객체 / 리필 남은 시간을 기록합니다.
- `Debug/재고 소진 및 리필 시작`: 객체를 삭제하거나 외부 재료를 회수하지 않고 공급 수량만 0으로 만듭니다. 외부 재료가 있어도 실행하며 이미 재고가 0이거나 획득 예약 중이면 거절합니다.
- 리필 게이지 연결은 [PARTY_PREPARATION](PARTY_PREPARATION.md#ingredient_refill), 사용자 확인은 [DONE](../DONE.md#공급원별-재료-재고와-재보충)을 따릅니다.

## CARROT_SOUP_SETUP

- CarrotSoupTestSetup은 생성 전에 고정 경로의 타입과 필수 참조를 검사합니다. 같은 경로의 다른 타입이나 불완전한 기존 Asset은 오류로 보고하며 자동 덮어쓰지 않습니다.
- 없는 Asset만 생성하고 기존 사용자 설정값은 보존합니다. 수량이나 가중치가 특정 값이라는 이유로 이전 기본값으로 추정해 바꾸지 않습니다. 기존 데이터 변경은 첫 미션 단계에 필요한 배치 미션이 없을 때 추가하는 범위입니다.
- 신규 생성 / 기존 수정 / 보존과 저장 / 실패 내역을 구분합니다. 생성 Asset과 실제 변경한 미션 단계만 저장하고 플레이 / 전환 중에는 적용하지 않습니다. 기존 단계 수정은 Undo를 지원하지만 전체 생성 작업의 완전한 Undo나 실패 시 자동 롤백은 보장하지 않습니다.

## TARGET_SELECTION_AND_ID

- 전체 선택은 기존 선택을 현재 검색 / 미부착 필터 결과로 교체합니다. 접힌 하위 대상도 포함하고 탐색용 부모는 제외합니다.
- Undo / Redo, 씬 Dirty와 프리팹 재정의 / 저장을 지원하고 YAML / .meta를 직접 편집하지 않습니다. 연출 삭제는 다른 기능의 직렬화 참조가 남는지 확인하고 결과를 보고합니다.
- 미리보기는 연출만 실행하며 실제 구매 / 제작 / 미션 / 보상 요청을 호출하지 않습니다. 편집 모드에서는 전용 시간 갱신과 기준값 스냅샷을 사용하고 중단 / 창 닫기 / 플레이 전환 / Assembly Reload에서 원상 복구합니다. 미리보기 중 상태를 새 기준으로 저장하지 않습니다.
- 플레이 중 값 변경은 임시 변경으로 표시합니다. 단일 / 혼합 값 일괄 수정, 기존 참조 보존, 누락 / 중복, 재실행과 Prefab Mode 저장을 실행 확인합니다.
