# 토끼 새 저폴리 모델 — 남은 작업 상세 계획

갱신일: 2026-10-02

## 현재 순서와 범위

**팔 복제 보류 → 한쪽 다리·발 → 전체 비율 검토 및 필요 시 한쪽 팔 재조정 → 확인 후 양쪽 적용 → 꼬리.**

이후 연결부·변형 topology·polygon budget을 정리하고 얼굴·UV·텍스처·리깅·Unity 검증으로 진행한다. 이후 항목은 잔여 작업 목록이며 이번 문서 요청으로 자동 실행하지 않는다. 사용자 최신 지시가 우선한다.

보호 규칙 참조인 `Rabbit_Modeling_Work_Rules.md`는 현재 저장소에서 찾을 수 없다. 모델링 재개 전 원문을 확인한다. 아래 명시된 원본 / 블록아웃 보호 조건은 유지하며 누락된 규칙을 임의로 재구성하지 않는다.

## 현재 상태

수정 대상은 Rabbit_LowPoly_V2_Work이다. low_poly_unwrapped는 원본 레퍼런스이며 메시·Transform 수정 금지다. Rabbit_LowPoly_Work는 첫 블록아웃 보존 대상이다.

새 모델의 머리·몸통은 사용자에게 긍정 평가를 받았다. positive-X, 정면 화면 오른쪽 팔·손만 원본 기반으로 재작업했다. 형태는 개선 평가를 받았지만 5cm 연장 후 길이는 잠정 상태다. 반대 팔과 양다리는 이전 형태다. 귀는 별도 메시 섬이며 뿌리 겹침이 남아 있다. 꼬리·얼굴 표현·UV·텍스처·리깅은 미완료다.

최근 저장 수치는 전체 1,675 vertices / 1,529 quads / 3,338 triangles다. 이번 문서 작성에서 다시 측정한 값은 아니다. 다음 작업 때 실제 씬과 파일을 확인한다.

## 1. 한쪽 다리·발의 기준 확인

다음 모델링 시작 때 씬을 읽고 복구본을 저장한다. 원본, 첫 블록아웃, 새 모델의 머리·몸통·귀·팔·반대 다리 좌표와 Transform을 보호한다.

원본과 시트에서 다음 항목을 정면·측면으로 대응시킨다.

- 골반의 다리 시작 위치와 양다리 사이 간격
- 허벅지 길이, 최대 폭과 깊이, 무릎 위치
- 무릎에서 종아리로 이어지는 폭 변화
- 발목 높이·폭·깊이와 다리 전체 길이
- 발의 정면 폭·측면 길이·높이, 발등 경사와 뒤꿈치 위치
- 발바닥 높이, 발끝 돌출 및 얕은 홈

측정 전에 새 단면 치수를 임의로 정하지 않는다. 원본은 실제 표면·치수·깊이, 시트는 정면·측면 외곽과 큰 면 구성을 함께 참고한다. 중요한 디자인 차이가 있으면 기존 합의를 먼저 찾고, 없을 때만 구체적으로 비교해 확인한다.

발은 기존 요청대로 하나의 둥근 큰 형태와 얕은 발끝 표현을 목표로 한다. 개별 발가락 분리나 관절은 필요하지 않다. 손의 “원본 외곽” 선택을 발에도 자동 적용하지 않는다.

## 2. 한쪽 다리·발 제작

positive-X 쪽 한쪽부터 제작해 수정된 팔과 같은 쪽 전체 비율을 볼 수 있게 한다. 반대쪽 복제와 꼬리는 진행하지 않는다.

1. 승인된 몸통·배 형태와 골반 연결 경계를 유지한다. 기존 다리 topology를 유지하는 것보다 참고 외곽 재현을 우선한다.
2. 골반→허벅지→무릎→종아리→발목의 큰 형태부터 만든다. 갑작스러운 좁아짐, 층진 폭 변화, 불필요한 돌출을 피한다.
3. 실제 원본 표면을 보고 국소 재구성 또는 표면 복사 후 감량 방식을 선택한다. 임의 링을 늘어놓고 원본 재현이라고 설명하지 않는다.
4. 발목에서 발로 자연스럽게 연결한다. 부츠처럼 급격히 넓어지는 전이를 피한다.
5. 정면 발 폭뿐 아니라 측면 길이·발등·뒤꿈치·바닥을 맞춘다. 외곽을 맞춘 뒤 얕은 발끝 굴곡을 정리한다.
6. 무릎·발목 변형용 루프를 두되 그 때문에 외곽이 부풀거나 잘록해지지 않게 한다. 변화가 적은 구간은 큰 면으로 구성한다.

몸통 경계 고정 때문에 형태를 맞출 수 없다면 제한을 보고한다. 몸통을 몰래 바꾸지 않는다. 전체 smooth·remesh·subdivision으로 국소 실패를 덮지 않는다.

제출: 전체 정면·측면·사선, 다리·발 확대, 원본/시트 대응 설명, 실제 polygon 수와 기술 검사 결과. 보호 부위 변경 여부도 보고한다.

## 3. 전체 비율과 한쪽 팔 재검토

한쪽 다리 제작 후, 복제 전에 다음을 비교한다.

- 머리·몸통·다리 길이와 전체 키
- 어깨→손목 길이와 손끝의 골반·허벅지 대비 높이
- 팔과 다리의 두께 관계, 손과 발의 크기 관계
- 측면에서 손·배·발의 앞뒤 위치
- 정면에서 몸통과 팔다리의 간격

현재 팔은 축 방향으로 0.05m 연장됐고 손 전체는 X +0.025m / Z -0.0433013m 이동했다. 손 최하단은 Z -0.421707m다. **이 값은 이력이며 확정 목표나 승인값이 아니다.**

필요하면 한쪽 팔을 추가 조정한다. 긍정 평가를 받은 손 외곽·크기와 어깨 위치를 유지한다. 손을 키워 팔이 길어진 것처럼 보이게 하지 않는다. 손 기준은 사용자 선택인 **원본 손 외곽 + 얕은 손가락 홈**이다.

전후는 동일 배율·카메라로 비교하고 필요하면 손목·손끝 높이 표시를 추가한다. 수치상 이동만으로 시각적 해결을 주장하지 않는다. 사용자 피드백을 반영하고 전체 비율이 확인되기 전에는 복제하지 않는다.

## 4. 반대쪽 적용

확인된 한쪽 팔다리만 반대쪽에 적용한다. 부위가 잠정 상태면 먼저 복제하지 않는다.

- 대칭 중심과 몸통 연결 경계를 확인한다. 머리·몸통을 함께 덮어쓰지 않는다.
- 현재 좌우 손의 정점 수가 다르므로 단순 좌표 복사가 아니라 해당 부위 면과 연결 경계를 교체한다.
- 접합의 구멍·중복 면·뒤집힌 normal·겹침을 검사한다.
- 양쪽 적용 후 정면·후면·측면·사선에서 간격과 포즈를 다시 확인한다.
- REGION 그룹의 좌우 이름과 부위 소속을 정리한다. 이 그룹은 실제 skin weight가 아니다.

제출: 양쪽 전체 실루엣과 연결 검사. 연결 과정에서 한쪽 확인본의 형태가 바뀌면 다시 비교한다.

## 5. 꼬리

팔다리 비율 정리 이후 꼬리만 별도 단계로 작업한다. 시트의 후면 위치·크기와 측면 돌출량, 원본의 입체 깊이를 확인한다. 임의의 공을 붙여 디자인을 새로 정하지 않는다.

적은 수의 큰 면으로 둥근 외곽을 맞춘다. 꼬리 위치를 확보하려고 몸통을 누르지 않는다. 애니메이션 요구와 최종 skinned mesh 구조에 따라 연결 방식을 정한다. 겹친 상태를 최종 연결이라고 보고하지 않는다. 후면·측면 비교 후 피드백을 반영한다.

## 6. 연결부와 변형 topology

형태 확인 이후 다음을 정리한다.

- 귀 외곽·끝·뿌리 형태를 보존하면서 머리와의 연결 구조를 해결한다. 현재 별도 귀 섬의 겹침은 미완료다.
- 목·어깨·팔꿈치·손목·골반·무릎·발목의 edge flow를 검토한다.
- 현재 어깨 흐름과 손목 삼각형 연결 띠를 우선 정리한다.
- 긴 삼각형, 과도한 pole, 중복 정점·내부 면·퇴화 면·loose geometry·normal·non-manifold·자기 교차를 검사한다.
- quad 중심을 유지하되 100% quad를 위해 실루엣·변형 품질을 희생하지 않는다.

변형 테스트 전에는 rig-ready라고 보고하지 않는다. 보호 오브젝트는 정리 대상에 포함하지 않는다.

## 7. Polygon budget과 저폴리 표현

30k를 채우는 목표는 폐기됐다. 다른 캐릭터는 약 4k triangles의 저폴리 스타일이다. 약 6k를 의식하는 초기 기준으로 필요한 만큼 사용하고, 형태·변형 확인 후 4k~5k 가능성을 검토한다. 최종 숫자는 아직 확정되지 않았다.

- 양쪽 팔다리·꼬리·연결부를 포함한 실제 전체/부위별 triangle 수를 측정한다.
- 귀·볼·손·발의 외곽과 관절 구조를 우선 보존한다.
- 이마·뒤통수·몸통 중앙·팔다리 중간의 불필요한 반복 분할을 줄인다.
- 큰 면의 방향과 표면 밀도를 정리한다. 숫자만 줄이고 불필요하게 매끈한 외곽을 유지하지 않는다.
- 다른 4k 캐릭터 자료가 있으면 같은 화면 크기·광원에서 비교한다. 자료 없이 스타일 일치 검증을 완료했다고 주장하지 않는다.
- shading과 normal 처리는 형상 검수 뒤 결정한다.

## 8. 얼굴·UV·텍스처

현재 새 모델의 얼굴 표현은 미완료다. 시트의 눈·코 위치·크기를 확인하고 texture 표현 또는 별도 geometry 필요 여부를 정한다. 표현 방식을 이미 확정한 것처럼 작업하지 않는다.

볼·배·귀 안쪽 색상은 Base Color로 표현한다. 색상 경계에 홈·돌출·단차를 만들지 않는다. 원본의 잘못된 무늬 geometry를 normal map에 다시 옮기지 않는다.

UV seam·texel density·손발귀 늘어짐·좌우 대칭 UV 여부를 확인한다. 새 topology에 기존 Meshy UV가 자동 유효하다고 가정하지 않는다. texture 해상도·재질 수·Unity shader는 프로젝트 요구를 확인한다.

## 9. 리깅·변형 테스트

형태와 연결 구조가 확인된 후 Humanoid/Generic, 귀·꼬리 본, 손의 개별 본 필요 여부를 결정한다. 현재 REGION 그룹을 skin weight 완료로 취급하지 않는다.

- 어깨: 팔 올리기·앞뒤 이동 / 팔꿈치: 굽힘 / 손목: 굽힘·회전
- 목: 회전·숙임 / 골반: 다리 들기·벌리기
- 무릎: 굽힘 / 발목: 발끝 들기·내리기
- 귀·꼬리: 실제로 움직이면 뿌리 회전·변형

외곽 손실·찌그러짐·관절 볼륨·면 교차를 확인한다. weight와 topology 문제를 구분해 수정하고 외곽이 바뀌면 형태 비교를 다시 한다.

## 10. Unity 6 전달·검증

제작 메시만 대상으로 단위·전체 크기·축·origin·Transform·export 구조를 확인한다. 원본과 첫 블록아웃을 잘못 export하지 않게 한다. 최종 triangulation 상태에서 숫자와 변형을 확인한다.

Unity에서 재질·texture 연결, skin weight·bone 구성, 크기·culling bounds·animation을 확인한다. 게임 카메라에서도 귀·손발 외곽과 관절 변형을 본다. 추가 LOD는 요구와 실제 필요에 따라 별도로 결정한다. 현재 Unity import 검증은 수행되지 않았다.
